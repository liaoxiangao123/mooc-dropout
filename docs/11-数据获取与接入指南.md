## 一、获取数据

**官方来源**：Biendata 的 KDD Cup 2015 赛题页
<https://www.biendata.xyz/competition/kddcup2015/data/>

步骤：

1. 注册并登录 Biendata 账号（需手机号验证）；
2. 进入赛题页 →「数据下载」，勾选同意竞赛协议；
3. 下载训练集压缩包（约 200~300 MB，解压后 `log_train.csv` 约 600 MB）。

**备选来源**（内容相同，任选其一）：

- **GitHub 镜像（已验证可用）**：`ryogrid/kddcup2015` 仓库根目录的 `train.7z`（约 44 MB）
  <https://github.com/ryogrid/kddcup2015>。国内网络下 `raw.githubusercontent.com` 常被掐断，
  可用加速代理：`https://gh-proxy.com/https://raw.githubusercontent.com/ryogrid/kddcup2015/master/train.7z`
  （实测约 100 KB/s）。解压后得到 `enrollment_train.csv`、`log_train.csv`、`truth_train.csv`。
- 注意：`ivanliu1989/KDD2015` 只有 R 代码与 PDF，**不含数据**，不要下那个。
- Kaggle 搜索 `KDD Cup 2015`（需登录，可用 Kaggle API 拉取）；
- 天池 / OpenDataLab / 各类高校镜像；
- 若拿到的是 `.rar`，Windows 上用 7-Zip 解压；`.7z` 可用 `py7zr` 或 7-Zip。

> 注意：Kaggle 与 HuggingFace 在本机网络下可能不可达（实测 HuggingFace 超时），
> 优先用 Biendata 或天池。

## 二、放置文件

```
data/raw/kdd2015/
├── enrollment_train.csv    必需
├── log_train.csv           必需
├── truth_train.csv         必需（若 enrollment 里没有 dropout 列）
├── object.csv              可选（当前特征未使用）
└── date.csv                可选（当前特征未使用）
```

`truth_train.csv` 与 `enrollment_train.csv` 分开是**官方原始结构**，加载器已支持自动合并。
如果你手上的是别人预处理过的合并版（enrollment 里直接有 `dropout` 列），只放两个文件即可。

## 三、验收

```bash
python scripts/check_data.py --data-dir data/raw/kdd2015
```

脚本会打印规模、辍学率、各课程辍学率范围、时间跨度、事件类型分布，并做一致性检查
（ID 对齐、重复、时间戳、观察窗覆盖）。**全部通过才继续训练**，否则先修数据。

参考规模（官方训练集，本机实测）：

| 指标 | 实测值 |
|---|---|
| 选课记录 | 120,542 条（其中 1 条 `139669` 无标签，自动剔除） |
| 学习者 | 79,186 人 |
| 课程 | 39 门 |
| 行为事件 | 8,157,277 条 |
| 时间跨度 | 2014-06-14 ~ 2015-03-18，共 278 天 |
| 辍学率 | **79.29%** |
| 事件构成 | access 38.15%、problem 15.46%、page_close 15.18%、navigate 12.37%、video 9.77%、discussion 7.96%、wiki 1.11% |

若你下载的数据规模与此差异巨大，先确认下的是不是 `train` 而非 `test` 压缩包。

> **早前版本的文档把辍学率写成「30%~40%」，是错的。** 官方标签的口径是「课程最后 10 天内
> 无任何行为」，而 MOOC 的整体完成率本来就只有 10%~20%，所以 79% 才是正常值。这个数字
> 直接决定了后面标签口径与代价参数怎么设计，见第七节。

## 四、训练与实验

```bash
# 单次训练（约 10~20 分钟，视 CPU）
python scripts/train.py --data-dir data/raw/kdd2015 --iterations 600

# 主实验（E1~E5）
python scripts/run_experiments.py --data-dir data/raw/kdd2015 --iterations 600

# 补充实验（E6~E8，5 个种子 × 4 个配置，耗时较长）
python scripts/run_extra_experiments.py --data-dir data/raw/kdd2015

# 超参搜索（E9）
python scripts/tune.py --data-dir data/raw/kdd2015 --trials 50
```

> `run_extra_experiments.py` 支持 `--data-dir`，换数据时无需改代码，直接传参即可。

## 五、已知的坑

| 坑 | 现象 | 处理 |
|---|---|---|
| `truth_train.csv` 无表头 | 首条记录被当成列名，少一条样本 | 加载器已自动探测表头并适配 |
| 内存不足 | 读取 600 MB CSV 时进程被杀 | 用 64 位 Python；必要时先过滤列；或读入时指定 `dtype={"object": str}` |
| 事件类型有未知值 | `出现未知事件类型: ['xxx']` | 在 `schema.py` 的 `KDD_EVENT_TYPES` 里补充，或清洗掉 |
| 时间格式不统一 | `无法解析的时间戳` | 统一为 `YYYY-MM-DD HH:MM:SS`，或让 pandas 推断 |
| 标签文件与选课表 ID 对不上 | `有 N 条选课在 truth 文件中找不到标签` | 官方数据本身有极少数无标签记录（如 `139669`）；≤1% 会被自动剔除并告警，超过 1% 才报错 |
| 中文路径/空格 | 读写报错 | 放在纯英文路径下 |

## 六、数据版本的学术声明

即使最终使用同构合成数据提交，也必须在论文 5.1.5 节保留数据版本声明，并在答辩时主动说明：

> 本文的模型排名与阈值结论来自同构数据集，其行为分布由生成过程设定；
> 真实数据上的绝对值会不同，但「加权破坏校准」「阈值需与代价同源」等方法论结论不依赖具体数据。

这样做不是扣分项——主动界定结论边界，比假装数据真实更可信。

## 七、标签口径：官方 79.29% 是多数类，必须做选择

这是接入真实数据后**最重要的一个问题**，比任何特征工程都关键。

官方标签 `dropout = 1` 的含义是「课程最后 10 天内没有任何行为」。在训练集上它占 79.29%，
是**多数类**。这直接推翻了两条常见前提：

1. **「辍学学生是少数类」不成立。** 论文若照抄「提高少数类识别能力」的表述，在真实数据上
   就是错的（合成数据辍学率 26% 时才成立）。
2. **代价最优决策有可能退化成「给所有人报警」。** 当 C_FN = 1000、C_FP = 100（ρ = 10）时，
   Elkan 阈值 p\* = 1/(1+ρ) = 0.0909。若校准后的概率分布满足 F(0.0909) ≈ 0（几乎没有学生
   的风险低于 9%），那么「全报警」既是代价最优又不可执行。退化的**充要条件**是
   F(p\*) ≈ 0，而不是「基率 > p\*」——高基率只是让 F(p\*) 变小的主要原因，不是充分条件。

   > ⚠️ 提醒：本文最初在真实数据上观察到「阈值恒为 0.01、人均代价等于基线 20.65 元」，
   > 一度把它解释为基率效应。**实际根因是 OOF 与标签错位的一个 bug**（见 7.3 节），
   > 修复后结论需要用重跑结果重新表述。遇到「模型完全失效」时，先核对 OOF 与测试集的
   > 指标是否自洽（OOF AUC 0.51 对测试集 0.82 就是典型指纹），再谈数据性质。

### 7.1 两条可选的标签口径

| 口径 | 定义 | 正类比例 | 适用场景 |
|---|---|---|---|
| **官方 dropout**（主口径） | 课程最后 10 天内无行为 | 79.29% | 与 KDD Cup 文献可比；用于讨论基率效应 |
| **早期辍学**（附口径） | 开课后 14 天内不再出现，且课程在其后仍有 ≥7 天 | 67.63% | 与 14 天观察窗的预测时点对齐，语义上更接近「可干预」 |

早期辍学标签由脚本派生，特征是流式读取的（8.16 M 条事件全量载入会吃掉 2 GB 内存）：

```bash
python scripts/derive_early_dropout.py --data-dir data/raw/kdd2015
```

脚本会先扫描 7/14/21/30 天四个候选窗口并打印辍学率，再按 `--window-days` 落盘
`data/processed/enrollment_early.csv`，同时把口径、比例、与官方标签的交叉表写进
`reports/早期辍学标签-统计.md`。

**无穿越保证**：特征只用 `[t0, t0+14d]` 内的事件，标签只看 14 天之后还来不来，两个时间
区间不重叠。观察期不足（课程在 14 天后只剩不到 7 天）的选课被剔除，否则会把「课已经上完」
误判成「学生辍学」。

### 7.2 换成早期辍学标签也还是多数类

实测发现早期辍学口径下正类仍有 67.63%（7 天 63.19%、21 天 69.60%）。这说明**高基率是
MOOC 数据的结构性特征**，靠重定义标签改变不了多少。它同时意味着退化解的风险始终存在，
因此评估口径本身必须升级，而不是继续找标签：

1. **报平凡基线**：`classification_metrics` 现在同时输出 `baseline_cost_all_positive`、
   `baseline_cost_all_negative`、`baseline_cost_trivial` 与 `cost_reduction_vs_trivial`。
   绝对代价没有意义，必须看相对下降。模型退化时该值恰为 0，一眼就能识别。
2. **扫描代价比**：`scripts/cost_ratio_scan.py` 固定 C_FP = ¥100、扫 ρ，用 OOF 预测重选
   阈值、在测试集上评估，**无需重新训练**，直接给出「退化解在哪个 ρ 之后消失」。
3. **改看容量曲线**：`scripts/capacity_analysis.py` 把决策规则换成「只能干预 K 个人，
   按风险排序取前 K」，回答教务处真正会问的问题——名单开多大、能抓住多少辍学生、
   前 K% 里的辍学生浓度是整体的几倍（lift）。lift 只取决于排序质量、与阈值无关，
   因此即使阈值视角失效，它仍能回答「模型有没有用」。

### 7.3 真实数据暴露的两个阈值相关 bug（已修）

**Bug 1：OOF 预测与标签错位（严重，只在非补零 ID 上触发）。**

`_oof_probabilities` 原来用一个 `positions` 映射把折内预测写回 `oof[行号]`，而行号是
`train_enrollments` 的行序；但下游 `cost_optimal_threshold(data.y_train, oof_prob)` 里的
`y_train` 是按 `X_train.index`（特征表按 enrollment_id **排序后**的顺序）取的标签。两者只在
「enrollment_id 的字典序 == 原始行序」时一致：

| 数据 | ID 形式 | 字典序 == 行序 | 是否触发 |
|---|---|---|---|
| 合成数据 | `E0000000`…（等宽补零） | 是 | 否 |
| 真实数据 | `1`,`2`,…,`120542` | **否**（`1`,`10`,`100`,…） | **是** |

触发后的症状极具迷惑性：**OOF AUC 0.5112，测试集 AUC 0.8205**。阈值搜索在一组被打乱的
标签上进行，代价曲线近乎平坦，argmin 落到网格最低点 0.01，看起来像「模型建议全报警」。
更糟的是校准器也在这对错位的 `(oof_prob, y_train)` 上拟合，于是保序回归把所有概率压成
常数 ≈ 0.79 —— `predicted_positive_rate` 在任何阈值下都是 1.0，彻底失去区分度。

修法：OOF 改为用 `enrollment_id` 作键的 Series，最后 `reindex(X_train.index)`，缺一条就报错，
不做静默填充。回归测试 `test_oof_predictions_align_when_enrollment_ids_sort_non_numerically`
把 ID 改成不补零形式并断言 OOF AUC > 0.6。**这条测试之所以必要，是因为合成数据的 ID
恰好补零，这个 bug 在合成数据上永远测不出来。**

**Bug 2：阈值搜索的网格分辨率不够。**

旧实现用 `np.linspace(0.01, 0.99, 99)` 等距网格。ρ = 10 时最优阈值在 0.09 附近，网格在这一段
只有 8 个候选点；概率整体偏低时最优解会直接撞到 0.01 这个**网格边界**。现改为精确搜索：
按概率降序排列后对每个 k（前 k 个报警）计算代价取最小，O(n log n) 一次扫描即全局最优。
`tests/test_cost.py::test_optimal_threshold_is_exact_below_grid_resolution` 锁住该行为。

> 这两个 bug 值得单独记一笔，因为它们都是**「看起来像结论的错误」**：Bug 1 会让模型显得
> 完全失效（代价等于平凡基线、AUC 掉到 0.5），Bug 2 会让阈值显得「永远选最低点」。若不做
> 数据规模与 AUC 的交叉核对（OOF 0.51 vs 测试 0.82 这种矛盾），很容易直接把它写成
> 「代价敏感学习在真实数据上无效」的错误结论。


## 八、真实数据实验的三条命令

```bash
# 1) 早期辍学标签（附口径）
python scripts/derive_early_dropout.py --data-dir data/raw/kdd2015

# 2) 主口径训练（官方标签，加权 + 等渗校准）
MOOC_ARTIFACTS_DIR=artifacts/realdata_official \
MOOC_REPORTS_DIR=reports/realdata_official \
python scripts/train.py --data-dir data/raw/kdd2015 --iterations 600 --n-splits 3 --calibration isotonic

# 3) 附口径训练（早期辍学）
MOOC_ARTIFACTS_DIR=artifacts/realdata_early \
MOOC_REPORTS_DIR=reports/realdata_early \
python scripts/train.py --data-dir data/raw/kdd2015 \
    --label-file data/processed/enrollment_early.csv \
    --iterations 600 --n-splits 3 --calibration isotonic

# 4) 两个分析（不需要重新训练，读的是落盘的 predictions_*.csv）
python scripts/cost_ratio_scan.py --auto
python scripts/capacity_analysis.py --auto
```
