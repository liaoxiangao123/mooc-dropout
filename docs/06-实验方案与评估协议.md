## 2. 数据与切分协议

| 项目 | 设定 | 理由 |
|---|---|---|
| 训练/测试 | 80% / 20%，按 `username` 分组 | 防同一用户跨集泄漏 |
| 阈值选择 | 训练集内 5 折分组 OOF | 测试集不参与任何调参 |
| 重复实验 | 3 个随机种子（42/7/2024），报告均值±标准差 | 避免单次切分的偶然性 |
| 观察窗 | 14 天（另做 7/21 天敏感性） | 与业务预警节奏对齐 |
| 缺失处理 | 无日志的选课不参与训练，记录数量 | 全 0 特征无信息量 |

## 3. 基线设置

| 模型 | 关键参数 | 代价处理 | 作用 |
|---|---|---|---|
| Logistic Regression | `max_iter=2000`，标准化 | 无（ρ=1） | 线性下界 |
| Random Forest | `n_estimators=300`，`min_samples_leaf=2` | 无 | 装袋树基线 |
| HistGradientBoosting | `max_iter=300`，`lr=0.05` | 无 | 提升树基线 |
| CatBoost（no cost） | `iterations=600, depth=6, lr=0.05` | 无 | 验证收益是否来自模型本身 |
| **CatBoost（cost-sensitive）** | 同上 + `class_weights=[1,10]` | 加权 + 阈值 | **本文方法** |

为公平起见：所有模型使用**同一份特征矩阵、同一切分、同一评估函数**。

## 4. 指标定义

| 指标 | 公式 / 说明 | 角色 |
|---|---|---|
| Recall | $TP/(TP+FN)$ | 少数类识别能力 |
| Precision | $TP/(TP+FP)$ | 干预名单的纯度 |
| F1 | 调和平均 | 综合 |
| PR-AUC | 精度-召回曲线下面积 | 不平衡数据的主排序指标 |
| ROC-AUC | 仅作参考 | 辅助 |
| Brier | $\frac1N\sum(\hat p-y)^2$ | 概率校准质量（**加权模型必须报告**） |
| **期望代价/人** | $\dfrac{C_{FN}\cdot FN+C_{FP}\cdot FP}{N}$ | **主指标** |
| 预警人数 | $\#\{\hat p \ge t^*\}$ | 业务可执行性 |

> 论文中必须明确：**主指标是期望代价/人，PR-AUC 次之，ROC-AUC 仅作参考**。这与「AUC 高就是好模型」的常见写法不同，是本文的方法论立场。

## 7. 统计显著性

单一随机切分的差异可能来自偶然，建议至少做其中一种：

1. **Bootstrap**：对测试集做 1000 次重采样，计算两模型代价差值的 95% 置信区间，区间不含 0 才可称"显著"；
2. **多随机种子**：3 个种子重复，报告均值 ± 标准差，配合配对 t 检验（样本量小时用 Wilcoxon）。

论文写法示例：

> 在 3 次随机切分下，代价敏感 CatBoost 的人均期望代价为 12.4±0.9 元，优于 HGBDT 的 18.7±1.3 元；Bootstrap 1000 次重采样得到的代价差 95% CI 为 [4.8, 7.9]，不包含 0。

## 9. 结果讨论的写作要点

**要写的**：

- 代价敏感带来的 Recall 提升与 Precision 下降是**预期 trade-off**，用代价曲线说明净收益为正；
- ρ 增大时预警人数单调上升，说明机制可控、可交给业务方调参；
- 若 CatBoost 相比 HGBDT 优势不明显，应诚实说明「收益主要来自代价机制而非模型结构」——这本身是有价值的结论。

**不要写的**：

- 不要只报 AUC 最好的一组；
- 不要把「测试集上调出来的阈值」当作方法贡献；
- 不要用 Accuracy 作为不平衡数据的主指标；
- 不要在样本量 < 1000 时下过强结论。
