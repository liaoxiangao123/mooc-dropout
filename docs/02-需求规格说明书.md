# 02 · 需求规格说明书（SRS）

**版本**：v1.0 ｜ **日期**：2026-10-22 ｜ **对应代码**：`src/mooc_dropout/`

---

## 1. 范围

本系统面向「课程运营者 / 辅导教师」角色，提供**选课级别的辍学风险预测**能力，包含离线训练与在线推理两部分。

**不在范围内**：学习者端界面、干预效果评估（A/B 实验）、多课程排课优化。

## 2. 角色与场景

| 角色 | 目标 | 典型操作 |
|---|---|---|
| 课程运营者 | 知道哪些学生需要干预 | 上传/接入行为日志 → 获取高风险名单 |
| 辅导教师 | 知道某个学生为什么危险 | 查询单个学生 → 查看风险因子 |
| 研究者（本人） | 复现实验、比较模型 | 运行训练/实验脚本 → 查看指标台账 |

## 3. 功能需求

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR-01 | 数据加载 | 读取 KDD Cup 2015 的 `enrollment_*.csv` 与 `log_*.csv`，字段自动校验 | P0 | 缺列/类型错误时抛出可读错误，不静默通过 |
| FR-02 | 数据质量校验 | 校验 ID 唯一、时间可解析、事件类型合法、标签为 0/1 | P0 | 非法数据 100% 被拦截（见 `tests/test_features.py`） |
| FR-03 | 观察窗裁剪 | 以每条选课的首个事件为 t0，仅保留 `[t0, t0+14d]` 的事件 | P0 | 窗口外事件不改变任何特征值 |
| FR-04 | 特征构建 | 产出 44 维特征（42 数值 + 2 类别），支持 fit/transform 与持久化 | P0 | 单条与批量结果一致；特征全部在字典中登记 |
| FR-05 | 防泄漏切分 | 按 `username` 分组切分训练/测试集 | P0 | 两侧用户集合无交集 |
| FR-06 | 代价敏感训练 | 支持正类加权（`C_FN/C_FP`）与无加权两种模式 | P0 | 高代价比下预警率不降低 |
| FR-07 | 基线对比 | 支持 LR / RF / HGBDT 三种基线 | P1 | 与主模型同切分、同评估 |
| FR-08 | 阈值决策 | 支持 `oof_cost` / `elkan` / `fixed` 三种阈值策略 | P0 | 阈值 ∈ (0,1)，且不来自测试集 |
| FR-09 | 指标评估 | 输出 PR-AUC/ROC-AUC/Recall/Precision/F1/Brier/期望代价/分级人数 | P0 | 全部指标写入 `reports/metrics.json` |
| FR-10 | 单条推理 | 输入一条选课的行为事件，输出概率、等级、top-5 因子 | P0 | P95 延迟 < 300ms（本地 CPU） |
| FR-11 | 批量推理 | 一次最多 500 条，返回逐条结果与汇总分级统计 | P1 | 汇总人数 = 明细条数 |
| FR-12 | 模型元信息 | 提供模型版本、阈值、代价矩阵、特征字典 | P1 | `/v1/model/info` 可直接支撑论文附录 |
| FR-13 | 概率校准 | 支持 Platt / 保序回归，校准器在 OOF 上拟合，阈值随之重选 | P1 | 校准后 Brier 下降且人均代价变化 < 1 个种子标准差 |
| FR-14 | 干预名单导出 | 批量结果可按风险降序导出 CSV，带优先级与首要风险因子 | P1 | 列名固定、UTF-8 BOM、`X-Total-Count` 与行数一致 |

## 4. 非功能需求

| 编号 | 类别 | 要求 | 落地手段 |
|---|---|---|---|
| NFR-01 | 可复现 | 固定随机种子，一条命令完成训练 | `random_seed`、`scripts/train.py` |
| NFR-02 | 性能 | 12 万选课训练 < 10 分钟；单条推理 P95 < 300ms | CatBoost CPU、特征向量化聚合 |
| NFR-03 | 可用性 | 模型缺失时服务仍可启动，`/ready` 返回 503 而非崩溃 | 仓储层 `ModelNotReadyError` |
| NFR-04 | 安全 | 不返回堆栈；CORS 显式白名单；密钥仅走环境变量 | 全局异常处理、`Settings` 校验 |
| NFR-05 | 可观测 | 每条日志为单行 JSON，含 `request_id` | `logging_config.py`、中间件 |
| NFR-06 | 可维护 | 控制器不含业务逻辑，服务层不依赖 HTTP | 分层设计 + 代码评审 |
| NFR-07 | 可测试 | 核心逻辑单测覆盖，接口有集成测试 | `pytest`，115 个用例，行覆盖 93% |
| NFR-08 | 可解释 | 每个预测返回可读的风险因子 | CatBoost 原生 SHAP |

## 5. 数据需求

| 数据 | 必需字段 | 说明 |
|---|---|---|
| 选课表 | `enrollment_id, username, course_id, dropout` | `dropout` 为 0/1 |
| 行为日志 | `enrollment_id, time, source, event, object` | `source` ∈ {access, discussion, navigate, page_close, problem, video, wiki} |

**数据量假设**：选课 ≥ 1000 条、日志 ≥ 5 万条（低于此规模指标方差过大，不作为结论依据）。

## 6. 接口需求（摘要）

| 方法 | 路径 | 输入 | 输出 | 错误 |
|---|---|---|---|---|
| GET | `/health` | — | `{status, version, env}` | — |
| GET | `/ready` | — | `{status, model_ready}` | 503 未就绪 |
| POST | `/v1/predict` | `PredictRequest` | `PredictResponse` | 422 参数错误 / 503 模型缺失 |
| POST | `/v1/predict/batch` | 最多 500 条 | `{items, summary}` | 同上 |
| GET | `/v1/model/info` | — | 模型与特征元信息 | 503 |

完整契约见 `docs/03` 第 6 节与 `/docs`（OpenAPI）。

## 7. 验收标准（Definition of Done）

一个功能算「完成」，必须同时满足：

1. 代码合并到主分支，`pytest -q` 全绿；
2. 有对应的测试用例（正常路径 + 至少 1 个异常路径）；
3. 文档中能查到该功能（需求编号 → 设计章节 → 代码文件 → 测试文件）；
4. 演示时能在 3 分钟内跑通，无需手工改代码。
